# vtirc-ng

A full-featured IRC client written in FreeBASIC on libvt (an SDL2 text-screen library). It targets **Windows 32-bit** and **Linux x86-64**. The original VTIRC 1.23 sources are in git history (first commit); `PLAN.md` holds the roadmap and the decisions behind it.

## Build and test

```bash
build/build.sh [linux64|win32|all|test] [release|debug]   # outputs in build/out/<target>/
tests/run_net.sh [port]      # network suite: starts tests/fakeircd.py, runs tests/test_net.bas
build/package.sh             # release archives in dist/
fbc vtirc.bas                # quick dev build (uses #cmdline flags)
```

- Always build with **FreeBASIC 1.10.1**. On this machine that is `/usr/local/bin/fbc` (a newer fbc in `~/fbdev/bin` comes first on PATH, and `build.sh` refuses any other version). The win32 build runs `fbc32.exe` from `~/freebasic/fb_programming/FreeBASIC-1.10.1-winlibs-gcc-9.3.0` under wine with `WINEPREFIX=~/.wine-fbc`. It links against `deps/win32/SDL2.dll`.
- Test suites:
  - `tests/test_core.bas` (unit and state tests, around 230 checks) uses a Linux `socketpair` as a fake server connection.
  - `tests/test_net.bas` (49 checks) covers TLS, pinning, SASL, SOCKS5, DCC and reconnect against `tests/fakeircd.py`.
  - Test builds use `-g -exx` (bounds checking). Both suites should stay clean under valgrind.
- **UI tests:** run the app with `SDL_VIDEODRIVER=offscreen VTIRC_TEST_SCRIPT=<script>` and `XDG_CONFIG_HOME=<tmp>`. Scripts use `src/ui/uitest.bas` commands (`wait`, `cmd`, `type`, `key`, `mouse`, `snap file.bmp`, `expect_active`, `quit`). Convert the BMPs with PIL to inspect them. The same works for `vtirc-ng.exe` under wine (put a `portable` file next to the exe).
- When starting `fakeircd.py` in the background, keep its PID (`python3 ... & PID=$!`) and `kill $PID`. Neither `pkill -f fakeircd` nor a `&&` chain before the `&` is safe.

## Layout

A single compilation unit: `vtirc.bas` includes `vt/vt.bi` (with `VT_USE_TUI`, `VT_USE_TLS`), then `src/core/core.bas`, the embedded font, then `src/ui/ui.bas`.

| Path | Role |
|---|---|
| `src/util/` | No libvt dependency: UTF-8 and display width (`fonts/unicode_width.bi`), bidi (UAX#9 subset), Arabic shaping, legacy code pages, ordered INI store, paths and portable mode, string, time and base64 helpers |
| `src/core/` | The IRC core; it never draws. `net` (connect thread, proxies, TLS), `ircmsg` (parser, case mapping), `model` (buffers, history rings, hashed user lists), `config`, `conn_types`/`conn` (state machine, send queue), `events` (printing, highlights, ignore, logging), `handlers` (every server message), `extras` (triggers, notify list, URL log), `dcc`, `commands` |
| `src/core/hooks.bi` | The only way the core talks to the front end (`ui_on_*`, `ui_active_buffer`, `ui_command`). Implemented in `src/ui/hooks_ui.bas`, stubbed in `tests/hooks_stub.bas` |
| `src/ui/` | `theme`, `text` (mIRC formatting to cells, wrapping, bidi per row, URLs), `render`, `input`, `notify`, `dialogs`, `uitest`, `app` (main loop, keys, mouse, menus) |
| `vt/` | Vendored libvt 1.11.0 with vtirc-ng changes, marked `vtirc-ng` in comments; `vt_uni.bas` is new |
| `src/fonts/`, `fonts/`, `tools/mkfont.py` | GNU Unifont: the embedded subset and the full `.vtuf` file, both generated by `tools/mkfont.py` from Unifont `.hex` files (not in the repo) |

## Architecture notes

- **Data model:** fixed pools. `bufs(0..511)` holds the windows (a buffer id is its slot index) and `conns(0..31)` the connections. Buffers keep `conn_id`, while connections keep their `status_buf`. Channel users are looked up through `uhash` (open addressing, with removal by swapping in the last user), so the order of `users()` is meaningless and display order comes from `user_sort` / `sorted()`.
- **Text:** stored as UTF-8 everywhere, with mIRC codes kept in history. Conversion to glyphs happens only in `src/ui/text.bas`, which applies Arabic shaping, then wrapping, then bidi per visual row. Selection and copy work on logical cell indices and the original bytes (`ucell.src`).
- **Main loop:** `app_main` drains keys, handles the mouse, renders when `ui_dirty` is set, then `vt_sleep(10)`. Network I/O runs from the libvt **idle callback** (`vt_on_idle`, called by every `vt_sleep`), so connections stay alive inside modal libvt menus and dialogs. Hooks must only set flags, never draw.
- **Unicode in libvt:** `vt_set_cell_ex` writes into a per-page extension plane. An entry only counts while the base cell still holds the `ch/fg/bg` it recorded, so libvt TUI widgets (CP437-only) override it just by drawing. Dialog lists use `ui_listbox_draw` for Unicode, with `Chr(1)` separating columns so bidi stays within each column.
- **Threads:** only `net_job` workers (resolve, connect, proxy and TLS handshake) run off the main thread. A cancelled job is parked in a zombie list and reaped later, because FB 1.10.1 has no `ThreadDetach`. The program must link only `-lfbmt`.
- **Config:** everything lives in `cfg_ini` (an ordered INI). The `app_settings` struct `cfg` and `nets()` are synced through `settings_from_ini` / `settings_to_ini` / `nets_*_ini`. A new setting needs the struct field, a default, the load and save lines, and ideally a `smeta` entry in `src/ui/dialogs.bas`.
- **Commands:** `cmd_reg` in `cmd_init()` (`src/core/commands.bas`). User aliases are checked first, then built-ins, then `ui_command`, then raw passthrough. Also update `help_text` when adding keys.

## FreeBASIC pitfalls met in this code

- Names are case-insensitive. An enum and a function called `BIDI_CLASS` / `bidi_class` clash.
- Keywords and built-ins that can't be used as identifiers: `cls`, `base`, `out`, `rgb`, `name`, `log`, `pos`, `window`, `field`, `var`, `data`, `line`, `color`, `width`, `exp`. Windows headers also claim `MSG` and `btype`. Pick other names (`kmsg`, `txt_out`, `rgbv`).
- A `Static` variable-length string can't have an initializer. `Get` into an empty string raises an error. Converting a ZString (`Left(zbuf, n)`) stops at NUL, so copy socket data with `memcpy` into `Space(n)`.
- fbc 1.10.1 crashes on one huge array initializer; `mkfont.py` writes 16 KB chunks instead.
- `Open ... For Binary Access Write` truncates an existing file. Use plain `For Binary` to append or resume.
- On Linux, SIGPIPE is ignored in `net_init`. On Windows, a refused non-blocking connect shows up in the `select` *exception* set (`net_wait_connect`).
- `ThreadCreate` without a stack size gives only **16 KB** on Linux (FB 1.10.1). A real DNS lookup or TLS handshake overflows it, so `net_job_start` passes `NET_THREAD_STACK` (1 MB). Pass a stack size for any new thread.
- Python edit scripts that contain FreeBASIC's `"""` break Python's triple quotes. Write such scripts to a file with `'''` strings.
